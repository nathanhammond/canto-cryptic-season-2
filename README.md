# Canto Cryptic season 2

`days/` contains all 32 pages rendered at 300 DPI from
`canto.cryptic season 2 standard.pdf`. The pages keep the orientation of the
source PDF. Day 16 has no cipher content in the PDF.

`characters/` contains the 23 normalized components supplied from day 31 rows
1-3 plus the subsequently confirmed missing components. They keep their source
orientation and need only one size. Each file uses a unique, similar-looking
lowercase letter, digit, or common symbol:

All template PNGs use an RGB white background. This keeps matching behavior
consistent across the original components and symbols extracted later.

The confirmed crossed/arched component is `f.png`. The short horizontal
`l.png` component is accepted only at the start of a line or after a visible
whitespace run, preventing it from matching arbitrary pieces of a baseline.

Run the original template matcher with:

```sh
uv run --with-requirements requirements.txt process.py
```

The generated annotated pages are written to `output/`. The matcher detects the
horizontal cipher baselines below the Chinese/English heading, then greedily
matches each line from left to right. Colored rectangles therefore follow the
reading sequence without overlapping. Red rectangles mark currently unmatched
regions that need review.

The `h` and `3` templates include a stroke shared with the component to their
left. The matcher excludes that fixed inset from their sequential span while
still using the complete template image for recognition, keeping their displayed
boxes sequential and non-overlapping.

Templates that are especially affected by neighboring strokes (`5`, `6`, `7`,
`8`, `h`, `j`, `p`, `s`, `t`, and `w`) use narrowly tuned confidence thresholds. The greedy scan
rejects matches that contribute only a sliver of new width and prefers a wider
complete glyph over a contained `-`/`z` stroke when their scores are close.

Two confirmed missing components use lowercase Greek names: `ω.png` for the
double-looped dome and `ϲ.png` for the narrow lunate curve.
The two-dots-under variant of `k` is named `#.png`, which keeps it distinct
from the Greek curve while remaining easy to type on a QWERTY keyboard.
The matcher distinguishes dot variants by counting compact marks in a narrow
window around the shared base. Above the baseline, zero maps to `-`, one to
`z`, and two to `o`; below it, zero maps to `k`, one to `q`, and two to `#`.
The lower window excludes the far-right and deeper area where dots belonging
to the following glyph can overlap.

`encoded_symbols.txt` contains one tab-separated encoded string per day. A `/`
preserves each source line break, and `?` marks an unmatched region. Day 16 is
present with an empty string.

`symbol_review.html` is a server-free browser review tool generated by the same
run. It groups every classified occurrence by symbol and supports day, language,
context, confidence, and source-order filters while drawing crops directly from
the existing `days/` images. Each crop is shown beside the expected template.
Clicking an occurrence opens replacement-symbol, missing-symbol, and segmentation
choices; decisions remain in browser storage and can be exported as
`symbol_review_edits.json`. When that file is placed in the project root, the
next matcher run applies valid reviewed replacements and segmentation removals.
`passages.csv` records each PDF page's first-line
description and language class. `sequence_report.md` compares contiguous
one-to-six-symbol sequences by genre and lists passage-unique signatures.

`missing_symbols/` is rebuilt on each run with deduplicated review candidates.
`index.csv` records each candidate's detected occurrences and source
coordinates. Candidate images include 24 pixels of neighboring context on both
sides because adjacent components can share strokes. To avoid creating hundreds
of one-off segmentation files, the folder keeps the 32 most recurrent residual
shape groups. Bar-only residuals are ignored, and detected rows with no template
matches are treated as descriptor text. Day 16 is skipped because its PDF page
contains no cipher content.
